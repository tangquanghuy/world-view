## 数据从哪来

唯一的数据契约是 `配置方案/后台世界引擎-三类演进版-v0.9.json`，具体在
`units[0].impl.sub.format.fields`。所有字段名、类型、枚举取值、数组上限都以它为准，
不要照着页面上现有的写法反推。

### 契约只记一类历史：世界变化

六个实体表（`bg_fixed_npc_state`、任务、事件、地区、势力……）主键都是 
ame`，
写入即覆盖——**某个人上一轮的状态、某条任务上一轮的阶段，写完就没了**。
契约专门有一节「状态继承与清理」说明这是设计而非疏漏：旧记录是连续状态，
不是逐字保留的历史档案，重要后果由引擎主动搬进当前状态里延续。

例外是 `change_updates`。它有一张自己的表 `bg_world_change_log`，主键是
`change_key`（`time|kind|source_type|source_name|target_name` 拼的去重键），
按主键 upsert，所以**每条新变化都是一行新记录，跨轮累积**。契约对这个字段的原话就是
「值得进入世界总览或**历史记录**的统一变化索引」。面板用的
`bg_world_structured_v09` 视图里，`changes` 一节按时间倒序取 **120 条**——
mock 里一轮 16 条，也就是说真实运行时这一个字段自己就攒着七八轮的历史。

**所以不要在浏览器里另存一份历史。** 曾经考虑过用 localStorage / IndexedDB 给
「事件日志」「查看全部」这类入口垫几条过往记录，两个理由都不成立：
该有历史的那一类后端已经有了，前端再存就是给权威日志做个更差的副本
（换台机器没有、清缓存就丢、还会跟那 120 条对不上）；
不该有历史的那一类，本地存了是在跟引擎对着干——引擎判定为已失效、已被覆盖的事实，
前端偷偷留一份摆回玩家面前，还没有任何机制知道它什么时候该过期。
真要做，值得做的只有一件：翻到 `changes` 末尾时说清楚"再往前的没有了"。

mock 的形态对齐该文件 `dataViews` 里的 **`bg_world_structured_v09`** 视图：
`rootKey` 是 `background_world`，下面八个分区 `world / changes / npcs / factions /
candidates / tasks / events / regions` 正好覆盖四个页面的全部需要，页面本来也是
通过 `AcuData.queryView` 读这个视图。所以 mock 不另发明格式。

```
后台世界引擎-三类演进版-v0.9.json   ← 契约与视图定义（不要改）
        │
        ├─ _tools/build-mock.cjs      读旧 demo，修枚举，补缺失字段，产出 mock
        │        ↓
        │   mock/world-state-v09.json + .js
        │        ↓
        └─ _tools/validate-mock.cjs   拿契约现读现验，枚举越界／超上限／字段缺失都会报
           _tools/check-vocab.cjs     核对 vocab.js 是否覆盖契约里每个封闭枚举
```

常用命令，在本目录下执行：

```bash
node _tools/build-mock.cjs        # 重建 mock
node _tools/validate-mock.cjs     # 契约校验，有违规时退出码非 0
node _tools/check-vocab.cjs       # 词典覆盖率
node _tools/shot.cjs 任务与事件.html   # 三档宽度截图 + 溢出／小字号／控制台告警体检
node _tools/asset-manifest.cjs    # 美术资产缺口统计
node _tools/dump-contract.cjs --enums   # 契约里所有封闭枚举速查
node _tools/field-coverage.cjs    # 契约七组字段有没有被负责它的那一页读到（不带参数查四页）
node _tools/shot-event.cjs        # 点开事件卡再截图，顺带验关联任务跳转
node _tools/type-probe.cjs        # 逐类文字量字号／行高／字重／对比度
node _tools/icon-probe.cjs        # 图标有没有吃到 CSS 的 color
node _tools/field-audit.cjs --all          # 四页逐条数据核对落点（三档宽度都跑），比 field-coverage 更细
node _tools/field-audit.cjs 势力与地区.html --no-attrs   # 单页，且不认 title，用来查有没有在糊审计
node _tools/shot-el.cjs 总览.html ".duo .panel" 出图名 1536 "#egoMore"  # 点几下再拍某个元素
node _tools/shot-open.cjs 势力与地区.html "#dossierBtn"  # 点开浮层再拍它（浮层默认关着，shot.cjs 拍不到）
node _tools/shot-pick.cjs 露西 1536        # 先选中某个角色再整页截图
node _tools/img-size.cjs 图.png            # 量像素尺寸，裁图前先量省得坐标全错
node _tools/crop-xy2.cjs 图.png x y 宽 高 缩放 出图名   # 按矩形裁并放大，比对原型局部用
node _tools/diff-shot.cjs 基准.png 对比.png             # 逐像素比对，重构样式时证明没回退
node _tools/graph-cross.cjs                # 关系图连线实际交叉多少处，顺带看主次分了几档
node _tools/copy-check.cjs                 # 标题／字段名有没有写成问句或文艺词组，同屏有没有重名小节
node _tools/dead-ui.cjs                    # 长得能点、点了什么都不发生的控件（不带参数查四页）
```

`shot.cjs` 的体检包含四项：横向溢出、小于 13px 的正文、控制台告警，以及**引用了不存在的
图标**——`<use href="#i-xxx">` 指向一个不存在的 symbol 时页面上只是一块空白，
把私有图标并进共享精灵时漏改一处就会这样，肉眼基本发现不了。

`dead-ui.cjs` 在页面脚本跑之前把 `addEventListener` 换掉，记下谁绑过 click，再回头看
每个 `button` / `[tabindex]` / `[role=button]`，它自己或任一祖先有没有绑上。光读源码查不出来：
这几页大量用事件委托，一个 handler 管一片；而且 `onclick=""` 属性根本不走 `addEventListener`，
得单独认，否则真接了的按钮会被报成死的。它分两档：**死**（点了毫无反应，是 bug）和
**吐司**（只弹一句「尚未接入」，是占位）。目前四页都是 0。

## 页面怎么搭

新页面的骨架照抄任一现有页：两行 `<link>` 引共享 CSS，`<body>` 开头一行
`<script src="shared/icons.js">`，末尾按 `mock → vocab → wtime → panel` 的顺序引脚本，
然后 `P.initChrome('侧栏高亮项')` 把顶栏时钟、导航、toast 一次装好。

这条规矩是补的。`任务与事件.html` 最早按原型整屏复刻时还没有 shared 层，
它**根本没引 `panel.js`**，自己搭了一套外壳：一份写死六项的侧栏（六项全点不动，
包括三个真实存在的页面）、一份自己的 toast、一份自己的 `renderHeader`。
外面看不出来，因为长得一模一样。新页面别再走这条路。

`shared/panel.js` 里已经有的东西，别在页面里重写一遍：

| 用途 | 调用 |
| --- | --- |
| 取数 | `P.DATA`（= `background_world`）、`P.arr`、`P.esc`、`P.$`、`P.$$` |
| 中文标签 | `P.L('组名', 值)` |
| 头像／纹章 | `P.avatarTag(名字或参与者, 类名, 性别)`、`P.avatarRow(列表)`、`P.participantList(列表)` |
| 势力／地区取图 | `P.crestFile(势力)`、`P.sigilFile(地区)`，按枚举众数选，取不到回落首字 |
| 字段名／值 | `P.fieldKey(图标, 名)`、`P.termRow([图标,名,值])`、`P.kvGrid(行数组, 列数)` |
| 颜色分配 | `P.hueCycler()` 造一个「同一个键永远同一色」的取色器 |
| 切页 | `P.pageSlice(列表, 每页上限, 页码)` → `{items, pages, page}`，条目摊匀，末页不会只站一个 |
| 翻页 | `P.renderPager(元素, {page, pages, total, unit, note, onGo})` |
| 其他 | `P.progressOf(任务)`、`P.timeHH(时间串)`、`P.toast(话)`、`P.hash(字符串)` |

人物头像不再靠写死的名字→文件映射：`P.avatarFile` 先查已画好的几位，其余按名字
稳定哈希从 `assets/avatars/avatar-{f,m,n}-NN.png` 里取，同一个名字每次都取到同一张。
立绘 `P.portraitFile` 同理。这样页面事先不知道会出现谁也不会开天窗。
候选人物的 `profile.gender` 是契约里明写的，`avatarTag` 会自动读；传名字字符串时
自己把性别作第三个参数递进来，否则只能落到中性池。

共享组件里几个容易各写一套的：**时间尺** `.ruler` / `.tick`（刻度由页面按本批数据的
实际时间跨度算，塞进 `--x`）、**空态** `.nodata`（`.mid` 撑满居中、`.box` 虚线框）、
**时间戳** `.tm`、**宽浮层** `.sheet` / `.sheet-box` / `.sheet-close`（遮罩 + 居中 +
1080px 可滚外壳，页面只管往 `.sheet-box` 里塞内容，另接「点遮罩关 / Esc 关 / ✕ 关」
三行；总览的关系全图和势力页的完整档案都用它）。浮层顶栏直接用 `.phead`，
内边距由 `.sheet .phead` 管（右边要给 ✕ 让位）——总览和势力页一度各自在行内写同一串魔数。
新页面别再造 `xxx-empty`、`.xx .tm` 这种同义类名或就地重写。

**浮层里面装什么，是各页自己的事。** 外壳共享到 `.sheet-box` 为止，往里就分家了：
角色档案是分节卡片网格（`.sheet-head` 带立绘 + `.sheet-grid` / `.sheet-cols` / `.sheet-sec`），
势力与地区是横铺宽表（`.dsheet`）。这两套长得不一样是因为装的东西不一样，
不是谁抄漏了——各自只有一处使用者，别为了"共享"把它们搬进 `console.css`。
提取的门槛是**第二个使用者**，不是"看着像能共用"。

反过来，只有一个页面在用的**页面专属拼装件不要**往 `shared/` 搬——角色档案的
`.slotcard`（契约外数值的虚线空槽）、`.dcard`（右栏详情小卡）都只此一家，
搬过去只会让共享文件变成杂物间。判据不是「用了几次」而是「它是不是一个能起名字的
通用组件」：横向时间轴 `.tl` 目前也只有任务与事件页在用，但它是个自洽的组件，
留在 `console.css` 里；`.slotcard` 是为某一块版面拼出来的，就该待在页面里。

起类名前先搜一遍四个页面。曾经 `.rrow` 在角色档案里是「关系行」、在势力与地区里是
「地区行」，两套完全不同的样式重名，现已拆成 `.relrow` / `.regrow`。

## 排版规矩

新页面照抄这三条，`_tools/type-probe.cjs` 会逐条量：

1. **正文一律 ≥14px。** 13px 只留给「字段名」这一种角色，而且必须同时满足下一条。
   曾经把 `deadline` / 
ext_update` / `blockers` / `updated_at` 四项全铺在任务卡上，
   卡片下半截变成一片 13px 灰字，信息是全了，可读性没了。卡片是扫读面，
   摆不下的进详情面板——那是分层，不是删减，`field-coverage.cjs` 会把两边一起算。
2. **字段名和字段值必须一眼分得开。** 字段名 = 图标 + 13px 半粗 + `var(--hue-ink)`；
   字段值 = 14px 常规 + `var(--ink2)`。只靠 1px 字号差和两级灰度是分不开的，
   六项排在一起就是一堵没有落点的字墙。页面里的 `fieldKey()` / `termRow()` 就是干这个的。
3. **对比度过 WCAG AA**（普通字 4.5，≥18.66px 或 ≥14px 粗体按 3.0）。

图标必须靠 `svg{fill:currentColor}` 才能吃到容器的 `color`——sprite 里的 `<symbol>`
不带 fill，少这一条全站图标会静默渲染成纯黑，容器上写的颜色一点都不起作用。
`_tools/icon-probe.cjs` 专门查这个。

## 文案规矩

这是给玩家看的界面，不是给运维看的控制台。屏幕上每一个字都要挣自己的位置。

1. **内部术语不上台面。**「势力拓扑」「自我中心网络」「DAG」「实体」这些是写代码时的说法。
   换成日常就有的词：势力格局、人际关系、资源储备。命名先问一句：
   一个只想看故事的玩家，会用这个词吗？
2. **不写操作说明。**「点选拓扑图上的盾形节点切换」这种话说明控件本身没做出可点的样子。
   能点的东西要靠光标、悬停反馈、边框让人看出来，不是靠一行小字教。
3. **不写图例。** 图上每条线都已经带了文字标签，再来一行「实线＝势力之间、虚线＝争夺关系」
   就是把同一件事说两遍。图例只在图确实无法自解释时才留，而那通常意味着图该重画。
   势力格局那张图的图例**进出过两轮**：第一次按这条删掉；后来背景线的标签改成悬停才现身，
   有人以「那条线现在没字了」为由加了回来，四项，常年占标题栏一行。第二次还是删。
   理由：背景线本来就是刻意压暗的一档——细、淡、不抢眼，它的名字在悬停时、在名录里、
   在完整档案里都取得到。**为一档故意压暗的东西作注，等于把它又提回台面**，
   那还压它做什么。删掉之后图照样读得懂：主线带文字标签和箭头，节点自己挂着状态。
4. **不复述屏幕上数得出来的数。**「共 4 个势力」而屏幕上正摆着四个盾——这行字没有信息。
   计数只在它说明了**看不见的东西**时才写：列表被翻页截断了、折叠区里还压着几条。
   **契约给数组定的上限不算「看不见的东西」，它根本不是世界里的事。**
   `areas` 最多八条是存储的规格，玩家不知道有这回事，也不会关心这个势力还能再占几处地方。
   这个错犯到第三次才收干净：角色档案页的关系面板副标题写过「固定人物上限 8 条」，
   卡片右上角挂过「1 / 5」角标，势力档案的「涉足地区」下面写过「上限 8 处」。
   那一格现在放这个数是由什么摊出来的——地区名——跟隔壁「外交关系」下面列关系类型是一个写法。
5. **副标题不是必填项。**`.phead .sub` 没话可说就空着，别为了版式对称硬凑一句。
6. **契约字段名不是文案，直译出来的多半是半吊子。**「登场时机」「为何还在观察」
   「复核条件」「对行动的影响」——这些是 `scene_entry`、`retention`、`review_condition`、
   `impact` 的直译，读着像人话，其实要拐几个弯才想明白在说什么。用户念了一遍之后的评价是
   「完全不明白这是啥意思」。判据不是「有没有照字段名翻译」，是**玩家扫过去要不要拐弯**。
   翻不出人话，通常说明这条字段本来就不是给玩家看的，见下。
7. **标题和字段名是名词，不是问句。** 这条是上一条的补丁。第 6 条说直译不行之后，
   角色档案页整页改成了口语疑问句——「这个人是谁」「知道些什么」「答应了谁什么」
   「在纠结什么」「眼下的难处」「常来往的人」，用户念完的评价是「伪人感非常强烈」。
   它们并不比「身份」「情报」「承诺」「抉择」「处境」「往来」更好懂，只是更长、
   更像 AI 在自言自语。**去黑话的解药是普通名词，不是把标题写成聊天。**
   同一套面板里 `势力与地区` 一直是对的，照它来：当前焦点、资源储备、对外关系、
   内部群体、最近动向。反方向也别过头——为了不像术语而硬凑文艺词组
   （「众人此刻」「新近事态」）同样是自作聪明。
   字段名一视同仁：一行里不能「职业」「年纪」跟「长什么样」混着来。
   `copy-check.cjs` 盯这一条。它还查同屏重名——两个小节同名会读成同一份东西写了两遍
   （摘要卡和它在浮层里的完整节该同名，那两者不同屏，工具内外分开比）。
   改到名词还不算完，**名词也分「一个词」和「一句话缩短的词」**：
   `observable_state` 一度叫「旁人看得见」，`relations` 里那批人一度叫「常来往的人」。
   两个都是名词短语，不是问句，可仍旧是把一句解释塞进标题的位置——
   现在是「可见」和「交际圈」。旁边那枚眼睛图标已经说了是"看"，标题只补它没说的那半句。
8. **契约的 `current_` 前缀不要搬到界面上。** 契约里 `current_use`、`current_basis`、
   `current_state`、`current_action` 带这个前缀，是为了跟历史值区分；
   界面本来就只显示当前值，照抄过来只剩公文腔——「当前占用」「当前限制」「事实依据」
   「正在执行」「造成的组织影响」，用户的评价是「这些措辞都非常的奇怪」。
   落到界面上就是两个字的普通名词：**用途、限制、依据、现状、立场、行动、影响**。
   顺带一个好处：字段名等宽，左边那道竖线自然就齐了。

### 不要把世界摘成仪表盘

第 4 条管的是单行文案，这一条管整块面板。四页上一共有过三处「概览格」，
删掉之后一共回收 828px，其中总览页直接短了 315px（1585 → 1270）。用户的原话是
「这些东西非常像监控面板和运维平台」——而这正是整个项目开头就写明不要的东西。

拆开看，一块概览格里通常混着两种东西，**两种都得删，但理由不一样**：

1. **数出来的计数。** 「冲突类事件 1 起」「在册势力 4 个」「涉足地区 2」——
   它们描述的是数据库有几行，不是世界发生了什么。玩家体验不到"注册了四个势力"，
   他体验到的是黑石港商会和灰鸦佣兵团在抢港口。而且这些数**旁边就摆着能数的列表**，
   犯的其实是第 4 条。势力档案那三格尤其典型：「外交关系 2 · 结盟／竞争」和
   「涉足地区 2 · 黑石港／旧港夜市」，总结的是同一张卡片再往下 100px 的
   「对外关系」「地区联系」两节**原样列着**的东西。
2. **算出来的等级。** 「风险等级 中等」「世界氛围 紧张」「民众情绪 不安」
   「资源状况 紧张」「最深一层 经营」——契约里没有这些字段，是前端拿本轮记录套 if 现算的。
   细看公式就知道它们经不起推敲：`资源状况 = 有阻塞项的任务 > 0 ? '紧张' : '稳定'`，
   一条任务受阻就把整个世界的"资源状况"打成紧张。**这不是氛围，是一个假装成氛围的 if。**
   更能说明问题的是：总览和任务页各有一格叫「世界氛围」，两边公式不同
   （一边数未收束事件 ≥2，一边数未结束冲突 >0），今天同时显示"紧张"纯属巧合。
   同一个词在两页给出不同判断，是这类自造指标的必然结局。

**为什么原型上有、照搬却不行**：原型那排数字是 18 / 7 / 5 / 23、势力 12 个——
按一个记录量很大的世界画的，一排大字撑得住。契约的实际量级是每类几条到十几条，
同一套版式渲染出来就是「1 起 / 1 条 / 4 个 / 1 人」。**版式是按数量级选的，
数量级变了版式就得换**，这跟"忠实复刻原型"不冲突。

留下来的只有一处，可以拿它当判据：总览侧栏那张卡写的是
「紧张 — 2 起事件尚未收束，另有 1 个地区在争夺中」。它是**一句点名了具体东西的话**，
读起来是旁白不是仪表。任务页留的那行「下一次检查 · 霜月13日 07:00」同理——
它是全场最早的一个 
ext_update`，单条在各自卡片上，跨任务和事件一起看才有这个数，
是真正看不见的信息。

契约自己也是这么说的，`macro_record_selection` 那条写着：
**「页面一级信息需要直接回答谁、何时、何地、正在做什么」**。计数和等级一条都不回答。

### 分清「人的事」和「系统的事」

契约是给引擎写的。同一张表里，有些字段描述世界里发生了什么，
有些字段描述引擎自己打算怎么跑——后者混进主视图，整页就会读起来像运行日志。

角色档案页踩得最深：`scene_entry`（这个 NPC 什么条件下能进玩家的场景）
和 `retention`（系统还要不要继续跟踪这个候选人）整整两块都是引擎的账，
`retention` 更是等于把回收策略贴在人物卡上。它们一度和「他在哪、他知道什么」
并排摆着，占的还是靠前的位置。

分法：**玩家扫这一页时会不会想知道这条。** 会，留在主视图；
不会但偶尔要查，进详情或浮层；两者都不是，收进一个明说「这是给引擎看的」的折叠区。
收起来不算删——数据一条不能少，`field-audit.cjs --no-attrs` 会盯着。

现在固定人物与候选人物共用同一套 `profile` 字段：职业、社会角色、年纪、性别、生计、常驻地、专长、外貌和性格标签。`profile` 只进角色档案展示视图，不进入 access 含 macro 的主 API 上下文；副 API 负责原样维护，动态状态仍由后台演进记录负责。

**契约里是两张表，列表里就得是两段。**
pc_updates` 和 `candidate_updates`
字段不同、状态词也是两套（在附近／视线外 对 观察中／可启用）。人物名册原来把两类
按 `updated_at` 混排，只在候选那几张卡右上角挂一枚「候选」角标——同一列里
状态词忽好忽坏，读起来像同一类记录时好时坏。现在分两段、各自按 `updated_at` 倒序，
段头写一次类名，角标跟着删：段头底下每张卡再挂一枚同义标签是重复的话。
翻页翻到半段中间会补一个段头，否则那一页开头认不出是哪类人。

## 版面松紧

信息密度不是越低越好，空得没道理和挤得看不清一样糟。

- 一屏之内同类卡片的呼吸感要一致，不能这张 20px 内边距那张 11px。
- 一大片留白后面跟着一小行字，说明这块的高度是被别的东西撑出来的，去查那个东西。
- 图形区（关系图、拓扑图、时间尺）的高度要跟着内容走，节点少就矮下来，
  不要固定高度然后中间空一大片。
- 长文本区块（事实陈述、依据、变化记录）宽度别超过 ~40 个汉字，超了就分栏或收窄。

### 窄栏放摘要，宽面放全量

侧栏是定宽的（350px 上下），**完整档案不该待在里面**。有两页栽在这上面：
势力档案把 35 个字段塞进 344px 的竖条、堆到 1520px；角色档案的「处境与近况」
八张卡竖着摞成 352×1722。两处都又窄又长，而且把行高压紧只能治「长」治不了「窄」。

看原型是怎么分的。它的侧栏每一节都是**一屏内看得完的摘要 + 一个出口**：

- 势力页：资源储备一整行三项（资金 / 物资 / 情报），外交状态五行一行一条，
  底下「展开更多」；再往下用标签页把三份清单叠进同一块地方。
- 角色页：基础属性 2 列网格、技能倾向 2 列网格、持有物横着一行四个、
  最近接触对象横着一行头像，每节右上角一个「查看全部 ›」。

两页原型都是整页一屏看完，靠的不是少放东西，是**横着铺**加**给出口**。
我们的毛病是把每一节都当成完整清单，一律竖着摞，`kvGrid()` 的列数永远传 1。

所以：

- 窄栏里能横着排的横着排——2 列网格、一行多项、一行头像。
- 每节只留摘要，完整内容走宽浮层（`.sheet` / `.sheet-box` / `.sheet-close`，
  1080px 宽，点遮罩关 / Esc 关 / ✕ 关）。1080px 里字段名和值能同行，
  窄条里被迫竖着叠的东西全能摊平，既不用折叠也不用翻页。
- **浮层默认是关着的，所以摘要里省掉的字段必须在浮层里真的排出来**，别两头都漏。

### 宽度花在多摆一条，不是摊开一条

契约把一条记录拆成五六个字段，是为了让引擎能分别更新——那是**存储**的拆法。
照搬成表格列，每条记录横着摊满一整行，就成了阅读的灾难：势力完整档案曾经是
1080px 五列，每格 150px，装五到十个字，一句「不能同时承担长期封港损失」折成三行，
读的人得自己把句子拼回去。用户的原话是「这些字段实在太碎了，阅读起来就很破碎」。

同样的宽度换个花法：**一行摆两条记录**，每条竖着排，附注能连着写三十几个字不折行。

```
✗ 五列 × 150px            ✓ 两列 × 507px
类型│数量  │当前占用│…      ⬡ 可动用 82,150 金币  [资金]
资金│可动用│港口修复│…        用途 港口修复与临时护卫
    │82,15│与临时护│…        限制 不能同时承担长期封港损失
    │0 金币│卫     │…        ✦ 追加南堤仓库守备预算
```

配套的四条：

- **列数交给 `auto-fit`，别写死两列。**一节里有几条记录是数据说了算：黑石港商会每节两条，
  星辉典籍会每节都只有一条——写死两列就是格格空着右半边，一整份档案看下来右边是条白带。
  `auto-fit` 会把整条空掉的轨道塌掉，一条记录就铺满一行。
  但**卡片撑满不等于字要撑满**：铺满时那格有 1000px，一行能排七十来个字，
  早过了读得舒服的长度，所以值上还得留 `max-width:42em`。
- **主句挑最有信息量的那个字段**（数量、对象名、事实本身），枚举字段做成胶囊跟在后面。
  反过来拿枚举当主句，一列记录的开头就都是一个干巴巴的词。
- **字段名走同一道竖线**（`grid-template-columns:auto minmax(0,1fr)`），值才对得齐。
- **「本轮无变化」是我们补的话，不是数据**，得比真变化淡一档，
  否则一屏扫下来分不清哪条动过。淡到 `--ink5` 会掉出 AA（实测 4.35），
  区别靠图标从主色变灰，不靠把字压得更淡。

### 卡片最贵的是宽度，别拿去养装饰件

活跃事件卡原来是左右两栏：52px 的圆标一栏，正文一栏。344px 的侧栏里，
圆标加间距加内边距吃掉 90px，正文只剩 218px——「下次检查　海盗代表答复停火文本」
后面那个「时」被挤到第二行独自站着，地点也常年折两行。四张卡摞出 700 多 px。

改成**图标跟标题同行，正文和页脚通栏**（原型本来就是这么摆的），
同一份文字拿到 308px：地点、下次检查全部收在一行，卡片从 185/211/164 矮到
140/163/163，摆四张只占原来摆三张的高度。

```
✗ 52px 圆标 │ 218px 正文        ✓ [30] 港口冲突升级      [已控制]
[◯]│港口冲突升级   [已控制]        双方停止靠近民用泊位，临时接触仍在继续
   │双方停止靠近民用泊位，          [冲突] ⚲ 黑石港
   │临时接触仍在继续                ⌂ 下次检查 海盗代表答复停火文本时
   │[冲突] ⚲ 黑石港
   │⌂ 下次检查 海盗代表答复停火文本
   │  时
```

同行之后要收的三个尾巴：

- **带图标的行写成 `14px | 1fr` 的网格，不要 flex。**flex 里那段裸文本是个匿名
  item，折行时第二行落在 item 自己的左边——看着像缩到图标底下去了。
- **圆标跟状态胶囊都咬第一行。**`.chip` 全局是 `align-self:flex-start`，
  圆标也顶格，再用 `margin-top:-4px` 把 30px 的方块骑到 22px 的首行上居中；
  用 `align-items:center` 的话标题一折三行，圆标居中、胶囊顶格，两个各站各的。
- **省下的半个字宽常常刚好够那一行收住。**标签和值之间原来是个全角空格（14px），
  换成 7px 外边距，1280 下三行里有两行就不折了；剩下的交给 `text-wrap:pretty`。

形状也跟着改了：圆形在这套图里是人物头像的形状，事件不是人，
所以圆标换成跟 `.pmark` 一致的圆角方块。

### 东西少的时候，是把盒子收窄，不是把东西摊开

上一条讲的是宽度别浪费在装饰件上，这一条讲宽度别浪费在空气上。角色档案页的
「日程与行动」和「人际关系」是同一个毛病的两种长相，用户圈出来的原话是
「能不能收紧凑一点」。

**日程带：卡片封了 300px 上限。**一天只有一条行动时，702px 的带子只用掉四成，
后面拖着 402px 空白。把上限去掉不等于把小卡吹成一张大牌——卡片一宽，
**卡内改横排**：图标、标题、时间、状态并成一行，地点／任务／事件并成一行，
四五行竖着摞的短句收成两行，面板从 344px 降到 198px。

量宽度用**容器查询**而不是媒体查询：同一张卡在一张、两张、三张时宽度分别是
694 / 342 / 225px，屏幕宽度却没变，媒体查询看不见这件事。三档门槛：

| 卡片内容宽 | 版式 | 出现在 |
|---|---|---|
| < 300px | 全竖排 | 三张及以上 |
| ≥ 300px | 时间和状态胶囊并一行，元信息并排 | 两张 |
| ≥ 440px | 卡头整个并成一行 | 一张（或末行落单的那张） |

门槛量的是**内容盒**：卡片 342px 减掉 24px 内边距只剩 318px，门槛写 320 就永远
不命中。这种差一点点的失手在页面上不报错，表现为"改了没反应"。

顺带一个收获：`flex:1 1 218px` 会让末行落单的卡长满整行，原来靠 `max-width` 摁住，
现在正好让它走宽档——1280 下三条日程排成 2+1，那张落单的自己摊平，没有豁口。

**关系图：画布跟着节点数收。**一条关系的图在 702px 里是两个节点各站一边、
中间一段空连线，两侧再各空一百五十像素。够摆下两个 120px 的节点盒加中间那枚
关系标签就行（一条 460px、两条 580px、三条 680px，四条以上本来就填得满）。
收窄之后右边空出两百多像素，把底下的「往来」清单挪过去并排——摞着是两段高度
之和，并排是取大的那个，面板 349px → 216px。够不够并排是**量出来的**
（`wrap.clientWidth - cap - 8 >= 250`），不是按屏幕断点猜的：1280 下同一个人就自动摞回去。

一个连带的坑：窄屏竖排的门槛 `TIGHT_W` 原来是个常数 470，是为多节点定的。
画布收到 460 之后一条关系的图被误判成窄屏，板高从 172 涨到 286——
**为收紧写的代码收出了一块更高的画布**。门槛跟着节点数走才对。

### 恒高的块提到通栏，会伸缩的块留在栏里

右栏定宽、左栏跟着屏幕变宽，于是屏幕越宽左栏越短、底下空得越明显。
总览的做法是拿真内容去补：关系明细折叠区（约 250px，粗调）和新近事态的每页条数
（约 46px 一条，细调），**先粗后细**，五档空档都压进 45px。补空的东西必须是真内容——
把关系图拉稀、给面板灌内边距都是作弊。

势力页不一样，它的空档来自「各地情势」是**读者自己能开合**的，高度摆 468→2613px。
配平是加载时算的，读者点一下「全部展开」就作废——那 43 行代码是在跟用户的手指赛跑。

第一版改法是把各地情势挪去通栏，让谁都不用跟它比高度。两栏差确实从 526～1619px
变成恒定 60px，但整页从 2180 长到 2412——**通栏的块跟谁都不共享纵向空间**，
本来能跟右栏 1186px 的势力档案并排的 900px，变成了实打实摞在底下的 900px。

第二版反过来：**把恒高的块提到通栏，让会伸缩的块留在栏里当配平的那一头。**

```
世界动向 209 ─┐ 恒高，通栏，摆最上面（也正好是最该先读到的两块）
名录     246 ─┘
────────────────────────────────
势力格局 675  │  势力档案 1186     左栏 = 675 + 各地情势
各地情势 500~ │                    收起时 1187 对 1186
```

结果：收起 1761（原来 1990）、默认 2174、全展开 3442，三档都比原版短，
而收起态两栏差 1px——那正是「地区全收起时中间很空」原本发生的那一档。

判据是**这一栏配平不过来的时候，空的是哪一头**：左栏短，空的是 974px 的主栏，很扎眼；
左栏长，空的是 344px 的窄条，末尾还压着「已推演到」那行，几乎看不出来。
所以让伸缩的那块待在左栏、只往长里跑，是可接受的方向。

后来又试了一次通栏（删掉档案卡三格概览、右栏矮了 162px 之后重量的），结论不变：

| 1536 档 | 各地情势在左栏 | 各地情势通栏 |
| --- | --- | --- |
| 全收起 | 1688px | 2021px |
| 展开一个 | 2101px | 2434px |
| 全部展开 | 3369px | 3667px |

**根因是这一块摊宽了并不会变矮**：收起态每行本来就是一行胶囊，974px 和 1330px
都是一行，宽度对它没用。所以通栏换不来任何高度，只是把它从"跟档案卡共享纵向空间"
改成"自己独占一段"，三档一律加三百多。空档也没省下——它从收起态的 165px
变成三种状态恒定的 347px（势力格局 675 对势力档案 1022）。
**要判断一块该不该提通栏，先量它在两种宽度下的高度差；差不出来就别提。**

剩下两个坑：

- 只调细的那样东西，旁边等高的面板会被拉高后自己空出一块——
  等于把洞从页面底部挪进了面板里，白改。
- 窄屏两栏其实是上下堆的，这时候比高度会把条数越削越少（实测从 5 削到 4）。
  配平前先判断两栏 `offsetTop` 是否相等。

顺带：**面板换了位置，里面的排法要跟着换。** 名录从 344px 的窄栏挪到 1300px 通栏，
原样竖着摞五条就是右边空一大片、页面白长 200px；改成 `auto-fill minmax(290px,1fr)`
之后 246px 装得下，比原来还矮。列宽也得跟着改——名字原来占 `1fr`，
会把状态胶囊一路顶到格子右边，多列下中间空一截，改成 `max-content` 才贴得住。

### 横排摆不下的用箭头翻，不要换第二排

改成横排之后剩一个尾巴：一排放得下四个，五个地区的第五个自己占第二排，
右边空掉四分之三排，面板还平白高一截。用户的话是「一行放不下的不要放两行，
做个左右箭头就行了」。**一整排是这个组件的形状，换行会把形状撑坏；
翻页不会。** 三件事配套：

- **一页放几条 = 一排摆得下几格**，量出来而不是写死（`idxPageSize`，
  跟底部时间线的 `wtlPageSize` 同一招：读 `grid-template-columns` 的轨道数）。
  写死 5 条，1300px 排四格就必然溢出一条。
- **页数定了之后把条目摊匀**，别每页都塞满：五条分两页是 3+2 不是 4+1，
  七条分三页是 3+2+2 不是 3+3+1。末页只站一个，跟第二排只站一个一样难看。
- **最小格宽跟着内容形状走。** 地区一条就是「名字＋状态胶囊」两行短字，230px 够用，
  五个地区一排摆得下，`1536` 上索性不用翻页；热点和关系每条带一两行叙述，300px 才不摞成四行。

同一招也适用于多行的网格，只是量的东西从"一排几格"变成**"几行"**。
总览的人物动态原来写死一页 9 个（照原型的三列九格），七个人就摆成 3+3+1，
末行两格空着，而它本来就是这一页最高的一块。改成 `ACT_ROWS=2` × 当前列数：
宽屏三列 6 人、1440 以下两列 4 人、单列封在 4（单列一页两格翻起来太碎）。
行数比格数好使，因为它跟着断点自己对齐，不会在两列档变成 4+4+1。
断点跨过去列数会变，所以 `resize` 里要重跑一遍。

这里跟上一条的"摊匀"**故意反着来**：横排那种一行的组件，末页只站一个很难看，
所以 5 条分 3+2；多行网格相反，第一页排满整行更重要——七个人 6+1
（首页两行齐平）胜过摊匀的 4+3（首页 3+1，反而多一个豁口）。
判据是**哪一页最常被看到**，把整齐留给它。

摊匀那段算法是 `P.pageSlice(列表, 每页上限, 页码)`，回传 `{items, pages, page}`。
势力页的名录和总览的活跃事件都走它；`page` 要写回调用方自己的页码变量，
不然窗口拉宽之后页数变少，页码会停在一个已经不存在的末页上。
竖排列表跟横排一样吃"末页只站一个"这一亏——一张孤零零的卡下面顶着翻页条，
比多滚两屏更像出了错。

翻页件也换了形状：底下一整行的翻页条（`.pg`，带「第 1/2 页　共 5 个地区」）
对一排格子来说太重，而且又多占一行——换成页签行右端一对圆箭头（`.stripnav`）。
两种翻页件的共同点是按钮上的 `data-d`，`field-audit.cjs` 认这个属性而不是 `.pg` 类名。
副标题那句「共 5 个地区」跟着没了，不算丢信息：底下「各地情势」把地区一条条列着。

## 长得能点，就得真能点

原型是张图，图上的按钮不用管点了以后怎么办；页面不是。一轮 `dead-ui.cjs` 扫出
四页共 10 处死控件、11 处只会弹「尚未接入」的占位，全清了。清的时候按这几条判：

1. **没有数据支撑的，删。** 顶栏的「速度倍率 × 2.0」是四页写死的一个数——契约里
   没有任何间隔、频率、速度字段（`间隔`／`频率`／`interval`／`cron` 全是 0 命中），
   推演由后台的 `bg_world_tick_v09` 驱动，页面是它的显示端，不是遥控器。
   那对「暂停中／继续」同理，是个只会弹吐司的假开关。侧栏的「世界设定」也没有对应产出。
2. **出口指回自己的，删。** 任务与事件页的「查看完整时间线 ›」和「活跃事件 › 查看全部」，
   要看的东西就在本页下面完整分页摆着。
3. **不归引擎管的，删，那句话搬进文档。**「编辑档案」的吐司写着"档案改不了，
   后台世界引擎只负责让世界往前走"——话说得对，但它该在这儿，不该是个按钮。
   「管理角色」「筛选」「搜索」「筛选与排序」同理，纯前端功能没做就先不摆。
4. **有真去处的，接上，别弹吐司告诉人家该去哪儿。** 势力页「完整时间线 ›」原来弹
   "完整世界演进流在世界演进页"，现在直接跳过去。
5. **点了只是复述屏幕上已有的字，等于点了个响。** 总览的事件卡原来挂
   `data-toast="事件名：当前局势"`，那两句就印在卡面上。改成跳到任务与事件页并选中它。
6. **导航项一律要有真页面。** 点了弹「尚未接入」的入口，比没有这个入口更糟：
   它承诺了一个不存在的地方。`NAV` 表里不留空 `href`，`initChrome` 里那条
   `if (!href) toast(...)` 的兜底也跟着删了——留着它就是给下一个人开口子。
7. **不要拿 div 模仿 button。** 事件卡原来一页是 `div` 挂吐司、另一页是
   `div + tabindex` 再手写 Enter/空格的 keydown。它只有「点开这个事件」一个用途，
   那就是 `<button>`，键盘、焦点环、语义浏览器都免费给。

最隐蔽的一种死不在这份清单里，因为按钮本身是活的：**它把活干给了一个不接的人。**
三个页面共五处「点一条任务／事件跳到任务页」都把名字写进 `sessionStorage.focusTask`
再跳，而那一页从来没读过这个键——落地永远是默认选中的第一条，点击的目标静默丢失，
而且看不出丢了。跨页传参必须两头都验一遍，`dead-ui.cjs` 查不出这种。

## 不做静默截断

页面上每个列表都比版面装得下的多。原来的写法是 `slice(0, 4)` 按数组位置切，
切掉哪些完全看运气——曾经把唯一一条受阻任务切没了，而且页面上不留任何痕迹。
现在统一改成：**按 `updated_at` 倒序排，四条一页，其余翻页看**，条数写在翻页条上。
时间轴摆不下 6 个以上，标题里明写「取最近 6 个（共 N 条）」。

同理，`first(a, b, c)` 这种「有 a 就不显示 b」的兜底也清掉了。它看着省地方，
实际效果是只要 `stages[].summary` 有值，`objective`（任务目标）就永远显示不出来。
现在 objective 与阶段摘要、deadline 与 next_update、trigger 与 current_state
各占各的位置。`field-coverage.cjs` 会盯着这件事，契约里 29 个任务／事件字段目前全覆盖。

这两件事查起来各有一个坑，都踩过了：

`field-coverage.cjs` 一度只有 `faction_updates` / `region_updates` 两组，
也就是四页里只覆盖了一页，而它的绿字被当成了四页的保证。现在七组齐全，
并且写死了**每组由哪一页负责排全**（`OWNER`）——别处出现的是摘要，不算落点。
契约里确实不该给玩家看的字段（`change_updates.change_key` 这种技术去重键）
单列进 `EXEMPT` 并写明理由，跟「漏了」区分开。

`field-audit.cjs` 一共踩过三个坑，每个都会让它输出假绿：

1. **看不见关着的浮层。**`hidden` 的 `.sheet` 是 `display:none`，正文一个字都不在
   `innerText` 里，但里面元素的 `title` 照样被抓到。三页都在走「窄栏摘要 + 宽浮层」
   之后，这个盲区会逼着页面在摘要行上挂一堆 `title` 去糊审计——而 `title` 恰恰是
   下面那条说的会消失的落点。现在抓文本前先点开出口再取消隐藏（顺序不能反，
   内容是点开时才渲染的），另外加了 `--no-attrs`：只认可见文本。
2. **只认得角色档案页。**「查哪些记录、怎么点开第 n 条」原来是写死人物列表的，
   给另外三页传文件名只会得到一句「查 0 项」——而重构那几页的时候恰恰最需要它。
   现在写在 `PAGES` 里，四页各一份，`--all` 一次跑完。改了记录的点开方式要跟着改这里。
   顺带统一了浮层入口的标记：凡是点开会另开一层的按钮都挂 `data-open-sheet`
   （三页原来各叫 `.dmore` / `#openFull` / `#dossierBtn`，审计只认得其中一个，
   于是另外两页的浮层内容从来没被审过）。
3. **翻页翻走的当成了丢。**列表分页是刻意取舍，跟「这条字段根本没排」是两回事。
   不翻一遍，凡是超出首页的记录都会被报成数据丢了，然后逼着页面取消分页去糊审计。
   现在每查一条记录前先把所有翻页条退回第一页，再逐页往后扫着抓文本。

三个坑填完，四页 624 个字段值 × 三档宽度全绿——在此之前只有角色档案一页是真被审过的。

还有一种更阴的漏法：**装饰性元素不能是某条契约字段的唯一落点**。
角色档案的 `schedule[].end_time` 一度只写在时间尺刻度的 `title` 里，而刻度会因为
版面变窄被挤掉——于是这条字段读不读得到取决于窗口多宽，1536 下审计永远是绿的。
凡是会随版面收起、折叠、改写的东西（时间尺刻度、并排才出现的副栏、悬停提示），
都要保证同一份信息在别处还有一个不会消失的落点。`field-audit.cjs` 因此改成三档都跑，
并会单独列出「换个宽度就找不到」的字段。

真正的清理该在数据层做——这些数据每轮都要回填进上下文，是实打实的 token。
见 `数据层待办.md`。页面这边只负责不隐瞒。

排序依赖时间可解析，而架空历法的月份是名字不是序号（`霜月` 排在 `花月` 前还是后，
程序无从判断）。`shared/wtime.js` 现在按「先在数据里出现的月份算更早」兜底，
同月内准确，跨月是猜的。根治办法也在 `数据层待办.md` 里。

## 改数据或改词典之前

`shared/vocab.js` 里每一组都对应契约中的一条枚举约束，组名后的注释写明了出处。
取标签必须带组名——同一个字符串在不同组里含义不同，例如 `planned` 是日程状态
（`schedule.status`）而不是阶段状态（`stage.status`，那里用的是 `available`）。
遇到词典里没有的值，`V.label` 会在控制台告警并原样返回，让契约漂移暴露出来，
而不是把英文枚举默默渲染给用户。

### 关于「主线任务」

契约对 `task.category` 的原文是：

> 只使用 main_task、side_task、character_task、faction_project、personal_task、other；
> **只有输入明确时区分主线和支线**。

宏观模块 `macro_task_creation` 里另有一条：「主线、支线等分类只在输入已有明确归类时采用，
**不由后台自行宣布**」。后台自主演进出来的任务默认落在 `character_task`、`faction_project`、
`personal_task` 这几类里，界面上不应该出现「主线」字样。上一代 demo 用的
`commission` / `investigation` / `escort` / `world_task` 全都不在枚举内。

## 建 mock 时修掉的契约违规

旧 demo 数据有 11 处枚举越界，接真实产出时会直接暴雷，已在 `build-mock.cjs` 里逐条修正：

| 位置 | 旧值 | 契约值 |
| --- | --- | --- |
| `tasks[].category` | `commission` / `investigation` / `escort` / `world_task` | `character_task` / `faction_project` |
| `tasks[].stages[].status` | `planned` | `available` |
| 
pcs[].knowledge[].status` | `likely` | `uncertain` |
| `events[].participants[].type` | `region` | `group` |
| `regions[].control.status` | `disrupted` / `open_with_restrictions` / `open` | `controlled` |
| `regions[].conditions[].category` | `transport`、`economy` | `travel`、`commerce` |
| `factions[].resources[].type` | `records` | `information` |
| `factions[].areas[].relation_type` | `contest` | `contested` |

另外补了两处缺失：

- **`changes` 集合**旧 demo 完全没有，而总览页需要它。现按契约从已完成的任务阶段、
  事件公开后果和地区变化派生，`change_key` 固定为 `time|kind|source_type|source_name|target_name`。
- **好感度**：契约里 
pcs[]` 和 `candidates[]` 的 `relations[]` 必带 `favorability`
  （0–100，50 为中性熟人）和 `favorability_change`，旧 demo 整个字段都没有。

## 原型上有、契约里没有的东西

四张原型图里画了一批数字，契约中并不存在，而且宏观规则明令禁止后台生成：

| 原型上的东西 | 契约实情 |
| --- | --- |
| 地区繁荣度、治安进度条 | `region_updates` 只有 `conditions[].fact` / `impact`，是事实不是评分 |
| 势力影响力 68/100、资源精确数字条 | `resources[].quantity` 是事实性字符串，明确要求「不自行制造精确数字」 |
| 人物基础属性、技能 LV、持有物 | 不属于后台世界引擎契约，不在面板占位 |
| 健康／体力／信任／好感四条状态槽 | 只有 `relations[].favorability`（0–100）是真的，其余三条没有来源 |

处理办法统一是**构图照抄，数字不编造**：位置和控件保留，但进度条只表达能从枚举推导的
强度（如 `control.status` 五档、`areas[].relation_type`），推导口径写进元素的 `title`；
没有数据来源的部分做成明确空态，说明等哪一路数据接入。要让这些真的有数，
得在契约里加字段，不是前端补。

空态别画成 0%。一条 0% 的实心进度条会被读成「这个数值是零」，而真相是后台根本不产出
这个数。角色档案用的是虚线胶囊（`.ghost`）：实心／描边表示「有值」，虚线表示「没有值」，
两者一眼分得开。目前只有那一页在用，第二个页面要表达同一件事时就该提进 `console.css`，
否则同一句话会长出四个样子。

## 还没做的

- **美术资产**，缺口、规格和分配规则见 `美术资产清单.md`。数据是 AI 每轮实时产出的，
  页面不知道渲染的是哪个人物、势力、地区，所以资产按可组合的通用件来做，不按实体出图。
  控制台那三个 404 是已知的装饰缺件，页面已做留白降级不会破图。
- **翻到 `changes` 末尾时没有说"到头了"**。那 120 条是视图给的上限，翻完不等于世界
  从那天开始——这正是「不做静默截断」那一节要求说出来的那种边界，翻页条现在只报
  「第 n / m 页　共 N 条」，没说 N 是被截过的。要等真接上后端、能拿到"是否还有更早"
  才好说，现在 mock 只有一轮 16 条，做了也验不出来。
- **`outcome` 这条路没跑过**。任务和事件终止后才有 `outcome`，当前 mock 里五条任务
  四条事件全是进行态，所以渲染代码写了但没有真数据走过。等 mock 里出现终止态条目
  （或者接了真实产出）要回头看一眼版式。
- **时间尺的防叠字只有角色档案有**。刻度取值是各页面自己算的，「等距挑第几个时间点」
  挑出来的不是等距的时间——赛文那天中间两个刻度只差五十分钟，390 档下相隔三十来像素
  直接糊成一团。角色档案加了按实际像素间距回收的逻辑，总览那份还没有。
  这段该做成 `P.renderRuler(元素, 时间串, {最小间距})` 收进 `panel.js`，两边共用。
- **暗底还没有令牌**。势力与地区的关系图是全站唯一一块深色画布，色值写死在那一页里
  （夜空往紫偏、地面掺赭石，跟暖白纸面同族，不能用冷灰蓝）。总览的「所有人的往来」
  浮层以后要走暗底就会各写一套，那时候在 `tokens.css` 开一组 `--night-*`。
- **标题字号还差一档没定死**。`.phead h2` 是 20px、`.dcard-h` 17px、`.sech` 15px。
  后两个目前只有角色档案在用，真要进共享层应该三档一起定成
  「面板 20 / 卡片 17 / 块内 15」，而不是单挪一个。
- **三页的栏高差没收**（1536 档量栏高）：任务与事件 1216 / 897（差 319），
  势力与地区收起态 1187 / 1022（差 165）、展开一个地区 1600 / 1022（差 578），
  角色档案 811 / 1418 / 1081（差 607）。总览靠 `balance()` 已经收到 61。
  差出来的就是页面底部那块白。**别拿加内容去填**——概览格当初就是这么长出来的。
  三条路都试过，只有第一条能用：换栏（总览的 `balance()`）；提通栏（势力与地区
  试过两次，每次都更长，见下）；靠数据自然长满（mock 里 `SUM_MAX=4` 根本没触顶，
  加不出内容来）。
  势力与地区那 165px 是删档案卡三格概览时空出来的，删之前两栏收起态只差 3px——
  纯属那三格恰好 162px 高，不是配平做对了。展开一个地区才差 578，
  那是手风琴张开的正常结果，不是版式漏洞。
- **两个工具有已知盲区**。`type-probe.cjs` 量得出字号、行高、字重、对比度，
  量不出「13px 用在了字段值上」「字段名没上主色」这类角色错配，只能靠眼睛。
  （它跟 `field-audit` 犯过同一个错：看不见关着的浮层，而浮层恰恰是排全量字段、
  字号最容易悄悄掉下去的地方。现在也先点 `data-open-sheet` 再量。）
  `graph-probe.cjs` 把所有 `path[stroke]` 都算成连线，所以画装饰路径必须写
  `style="stroke:..."` 而不是 `stroke` 属性，否则地平线和罗盘会被算成边。

## 数据从哪来

唯一的数据契约是 `配置方案/后台世界引擎-三类演进版-v0.9.json`，具体在
`units[0].impl.sub.format.fields`。所有字段名、类型、枚举取值、数组上限都以它为准，
不要照着页面上现有的写法反推。

### 契约只记一类历史：世界变化

六个实体表（`bg_fixed_npc_state`、任务、事件、地区、势力……）主键都是 
ame`，
写入即覆盖——**某个人上一轮的状态、某条任务上一轮的阶段，写完就没了**。
契约专门有一节「状态继承与清理」说明这是设计而非疏漏：旧记录是连续状态，
不是逐字保留的历史档案，重要后果由引擎主动搬进当前状态里延续。

例外是 `change_updates`。它有一张自己的表 `bg_world_change_log`，主键是
`change_key`（`time|kind|source_type|source_name|target_name` 拼的去重键），
按主键 upsert，所以**每条新变化都是一行新记录，跨轮累积**。契约对这个字段的原话就是
「值得进入世界总览或**历史记录**的统一变化索引」。面板用的
`bg_world_structured_v09` 视图里，`changes` 一节按时间倒序取 **120 条**——
mock 里一轮 16 条，也就是说真实运行时这一个字段自己就攒着七八轮的历史。

**所以不要在浏览器里另存一份历史。** 曾经考虑过用 localStorage / IndexedDB 给
「事件日志」「查看全部」这类入口垫几条过往记录，两个理由都不成立：
该有历史的那一类后端已经有了，前端再存就是给权威日志做个更差的副本
（换台机器没有、清缓存就丢、还会跟那 120 条对不上）；
不该有历史的那一类，本地存了是在跟引擎对着干——引擎判定为已失效、已被覆盖的事实，
前端偷偷留一份摆回玩家面前，还没有任何机制知道它什么时候该过期。
真要做，值得做的只有一件：翻到 `changes` 末尾时说清楚"再往前的没有了"。

mock 的形态对齐该文件 `dataViews` 里的 **`bg_world_structured_v09`** 视图：
`rootKey` 是 `background_world`，下面八个分区 `world / changes / npcs / factions /
candidates / tasks / events / regions` 正好覆盖四个页面的全部需要，页面本来也是
通过 `AcuData.queryView` 读这个视图。所以 mock 不另发明格式。

## 页面怎么搭

新页面的骨架照抄任一现有页：两行 `<link>` 引共享 CSS，`<body>` 开头一行
`<script src="shared/icons.js">`，末尾按 `mock → vocab → wtime → panel` 的顺序引脚本，
然后 `P.initChrome('侧栏高亮项')` 把顶栏时钟、导航、toast 一次装好。

这条规矩是补的。`任务与事件.html` 最早按原型整屏复刻时还没有 shared 层，
它**根本没引 `panel.js`**，自己搭了一套外壳：一份写死六项的侧栏（六项全点不动，
包括三个真实存在的页面）、一份自己的 toast、一份自己的 `renderHeader`。
外面看不出来，因为长得一模一样。新页面别再走这条路。

`shared/panel.js` 里已经有的东西，别在页面里重写一遍：

| 用途 | 调用 |
| --- | --- |
| 取数 | `P.DATA`（= `background_world`）、`P.arr`、`P.esc`、`P.$`、`P.$$` |
| 中文标签 | `P.L('组名', 值)` |
| 头像／纹章 | `P.avatarTag(名字或参与者, 类名, 性别)`、`P.avatarRow(列表)`、`P.participantList(列表)` |
| 势力／地区取图 | `P.crestFile(势力)`、`P.sigilFile(地区)`，按枚举众数选，取不到回落首字 |
| 字段名／值 | `P.fieldKey(图标, 名)`、`P.termRow([图标,名,值])`、`P.kvGrid(行数组, 列数)` |
| 颜色分配 | `P.hueCycler()` 造一个「同一个键永远同一色」的取色器 |
| 切页 | `P.pageSlice(列表, 每页上限, 页码)` → `{items, pages, page}`，条目摊匀，末页不会只站一个 |
| 翻页 | `P.renderPager(元素, {page, pages, total, unit, note, onGo})` |
| 其他 | `P.progressOf(任务)`、`P.timeHH(时间串)`、`P.toast(话)`、`P.hash(字符串)` |

人物头像不再靠写死的名字→文件映射：`P.avatarFile` 先查已画好的几位，其余按名字
稳定哈希从 `assets/avatars/avatar-{f,m,n}-NN.png` 里取，同一个名字每次都取到同一张。
立绘 `P.portraitFile` 同理。这样页面事先不知道会出现谁也不会开天窗。
候选人物的 `profile.gender` 是契约里明写的，`avatarTag` 会自动读；传名字字符串时
自己把性别作第三个参数递进来，否则只能落到中性池。

共享组件里几个容易各写一套的：**时间尺** `.ruler` / `.tick`（刻度由页面按本批数据的
实际时间跨度算，塞进 `--x`）、**空态** `.nodata`（`.mid` 撑满居中、`.box` 虚线框）、
**时间戳** `.tm`、**宽浮层** `.sheet` / `.sheet-box` / `.sheet-close`（遮罩 + 居中 +
1080px 可滚外壳，页面只管往 `.sheet-box` 里塞内容，另接「点遮罩关 / Esc 关 / ✕ 关」
三行；总览的关系全图和势力页的完整档案都用它）。浮层顶栏直接用 `.phead`，
内边距由 `.sheet .phead` 管（右边要给 ✕ 让位）——总览和势力页一度各自在行内写同一串魔数。
新页面别再造 `xxx-empty`、`.xx .tm` 这种同义类名或就地重写。

**浮层里面装什么，是各页自己的事。** 外壳共享到 `.sheet-box` 为止，往里就分家了：
角色档案是分节卡片网格（`.sheet-head` 带立绘 + `.sheet-grid` / `.sheet-cols` / `.sheet-sec`），
势力与地区是横铺宽表（`.dsheet`）。这两套长得不一样是因为装的东西不一样，
不是谁抄漏了——各自只有一处使用者，别为了"共享"把它们搬进 `console.css`。
提取的门槛是**第二个使用者**，不是"看着像能共用"。

反过来，只有一个页面在用的**页面专属拼装件不要**往 `shared/` 搬——角色档案的
`.slotcard`（契约外数值的虚线空槽）、`.dcard`（右栏详情小卡）都只此一家，
搬过去只会让共享文件变成杂物间。判据不是「用了几次」而是「它是不是一个能起名字的
通用组件」：横向时间轴 `.tl` 目前也只有任务与事件页在用，但它是个自洽的组件，
留在 `console.css` 里；`.slotcard` 是为某一块版面拼出来的，就该待在页面里。

起类名前先搜一遍四个页面。曾经 `.rrow` 在角色档案里是「关系行」、在势力与地区里是
「地区行」，两套完全不同的样式重名，现已拆成 `.relrow` / `.regrow`。

## 排版规矩

新页面照抄这三条，`_tools/type-probe.cjs` 会逐条量：

1. **正文一律 ≥14px。** 13px 只留给「字段名」这一种角色，而且必须同时满足下一条。
   曾经把 `deadline` / 
ext_update` / `blockers` / `updated_at` 四项全铺在任务卡上，
   卡片下半截变成一片 13px 灰字，信息是全了，可读性没了。卡片是扫读面，
   摆不下的进详情面板——那是分层，不是删减，`field-coverage.cjs` 会把两边一起算。
2. **字段名和字段值必须一眼分得开。** 字段名 = 图标 + 13px 半粗 + `var(--hue-ink)`；
   字段值 = 14px 常规 + `var(--ink2)`。只靠 1px 字号差和两级灰度是分不开的，
   六项排在一起就是一堵没有落点的字墙。页面里的 `fieldKey()` / `termRow()` 就是干这个的。
3. **对比度过 WCAG AA**（普通字 4.5，≥18.66px 或 ≥14px 粗体按 3.0）。

图标必须靠 `svg{fill:currentColor}` 才能吃到容器的 `color`——sprite 里的 `<symbol>`
不带 fill，少这一条全站图标会静默渲染成纯黑，容器上写的颜色一点都不起作用。
`_tools/icon-probe.cjs` 专门查这个。

## 文案规矩

这是给玩家看的界面，不是给运维看的控制台。屏幕上每一个字都要挣自己的位置。

1. **内部术语不上台面。**「势力拓扑」「自我中心网络」「DAG」「实体」这些是写代码时的说法。
   换成日常就有的词：势力格局、人际关系、资源储备。命名先问一句：
   一个只想看故事的玩家，会用这个词吗？
2. **不写操作说明。**「点选拓扑图上的盾形节点切换」这种话说明控件本身没做出可点的样子。
   能点的东西要靠光标、悬停反馈、边框让人看出来，不是靠一行小字教。
3. **不写图例。** 图上每条线都已经带了文字标签，再来一行「实线＝势力之间、虚线＝争夺关系」
   就是把同一件事说两遍。图例只在图确实无法自解释时才留，而那通常意味着图该重画。
   势力格局那张图的图例**进出过两轮**：第一次按这条删掉；后来背景线的标签改成悬停才现身，
   有人以「那条线现在没字了」为由加了回来，四项，常年占标题栏一行。第二次还是删。
   理由：背景线本来就是刻意压暗的一档——细、淡、不抢眼，它的名字在悬停时、在名录里、
   在完整档案里都取得到。**为一档故意压暗的东西作注，等于把它又提回台面**，
   那还压它做什么。删掉之后图照样读得懂：主线带文字标签和箭头，节点自己挂着状态。
4. **不复述屏幕上数得出来的数。**「共 4 个势力」而屏幕上正摆着四个盾——这行字没有信息。
   计数只在它说明了**看不见的东西**时才写：列表被翻页截断了、折叠区里还压着几条。
   **契约给数组定的上限不算「看不见的东西」，它根本不是世界里的事。**
   `areas` 最多八条是存储的规格，玩家不知道有这回事，也不会关心这个势力还能再占几处地方。
   这个错犯到第三次才收干净：角色档案页的关系面板副标题写过「固定人物上限 8 条」，
   卡片右上角挂过「1 / 5」角标，势力档案的「涉足地区」下面写过「上限 8 处」。
   那一格现在放这个数是由什么摊出来的——地区名——跟隔壁「外交关系」下面列关系类型是一个写法。
5. **副标题不是必填项。**`.phead .sub` 没话可说就空着，别为了版式对称硬凑一句。
6. **契约字段名不是文案，直译出来的多半是半吊子。**「登场时机」「为何还在观察」
   「复核条件」「对行动的影响」——这些是 `scene_entry`、`retention`、`review_condition`、
   `impact` 的直译，读着像人话，其实要拐几个弯才想明白在说什么。用户念了一遍之后的评价是
   「完全不明白这是啥意思」。判据不是「有没有照字段名翻译」，是**玩家扫过去要不要拐弯**。
   翻不出人话，通常说明这条字段本来就不是给玩家看的，见下。
7. **标题和字段名是名词，不是问句。** 这条是上一条的补丁。第 6 条说直译不行之后，
   角色档案页整页改成了口语疑问句——「这个人是谁」「知道些什么」「答应了谁什么」
   「在纠结什么」「眼下的难处」「常来往的人」，用户念完的评价是「伪人感非常强烈」。
   它们并不比「身份」「情报」「承诺」「抉择」「处境」「往来」更好懂，只是更长、
   更像 AI 在自言自语。**去黑话的解药是普通名词，不是把标题写成聊天。**
   同一套面板里 `势力与地区` 一直是对的，照它来：当前焦点、资源储备、对外关系、
   内部群体、最近动向。反方向也别过头——为了不像术语而硬凑文艺词组
   （「众人此刻」「新近事态」）同样是自作聪明。
   字段名一视同仁：一行里不能「职业」「年纪」跟「长什么样」混着来。
   `copy-check.cjs` 盯这一条。它还查同屏重名——两个小节同名会读成同一份东西写了两遍
   （摘要卡和它在浮层里的完整节该同名，那两者不同屏，工具内外分开比）。
   改到名词还不算完，**名词也分「一个词」和「一句话缩短的词」**：
   `observable_state` 一度叫「旁人看得见」，`relations` 里那批人一度叫「常来往的人」。
   两个都是名词短语，不是问句，可仍旧是把一句解释塞进标题的位置——
   现在是「可见」和「交际圈」。旁边那枚眼睛图标已经说了是"看"，标题只补它没说的那半句。
8. **契约的 `current_` 前缀不要搬到界面上。** 契约里 `current_use`、`current_basis`、
   `current_state`、`current_action` 带这个前缀，是为了跟历史值区分；
   界面本来就只显示当前值，照抄过来只剩公文腔——「当前占用」「当前限制」「事实依据」
   「正在执行」「造成的组织影响」，用户的评价是「这些措辞都非常的奇怪」。
   落到界面上就是两个字的普通名词：**用途、限制、依据、现状、立场、行动、影响**。
   顺带一个好处：字段名等宽，左边那道竖线自然就齐了。

### 不要把世界摘成仪表盘

第 4 条管的是单行文案，这一条管整块面板。四页上一共有过三处「概览格」，
删掉之后一共回收 828px，其中总览页直接短了 315px（1585 → 1270）。用户的原话是
「这些东西非常像监控面板和运维平台」——而这正是整个项目开头就写明不要的东西。

拆开看，一块概览格里通常混着两种东西，**两种都得删，但理由不一样**：

1. **数出来的计数。** 「冲突类事件 1 起」「在册势力 4 个」「涉足地区 2」——
   它们描述的是数据库有几行，不是世界发生了什么。玩家体验不到"注册了四个势力"，
   他体验到的是黑石港商会和灰鸦佣兵团在抢港口。而且这些数**旁边就摆着能数的列表**，
   犯的其实是第 4 条。势力档案那三格尤其典型：「外交关系 2 · 结盟／竞争」和
   「涉足地区 2 · 黑石港／旧港夜市」，总结的是同一张卡片再往下 100px 的
   「对外关系」「地区联系」两节**原样列着**的东西。
2. **算出来的等级。** 「风险等级 中等」「世界氛围 紧张」「民众情绪 不安」
   「资源状况 紧张」「最深一层 经营」——契约里没有这些字段，是前端拿本轮记录套 if 现算的。
   细看公式就知道它们经不起推敲：`资源状况 = 有阻塞项的任务 > 0 ? '紧张' : '稳定'`，
   一条任务受阻就把整个世界的"资源状况"打成紧张。**这不是氛围，是一个假装成氛围的 if。**
   更能说明问题的是：总览和任务页各有一格叫「世界氛围」，两边公式不同
   （一边数未收束事件 ≥2，一边数未结束冲突 >0），今天同时显示"紧张"纯属巧合。
   同一个词在两页给出不同判断，是这类自造指标的必然结局。

**为什么原型上有、照搬却不行**：原型那排数字是 18 / 7 / 5 / 23、势力 12 个——
按一个记录量很大的世界画的，一排大字撑得住。契约的实际量级是每类几条到十几条，
同一套版式渲染出来就是「1 起 / 1 条 / 4 个 / 1 人」。**版式是按数量级选的，
数量级变了版式就得换**，这跟"忠实复刻原型"不冲突。

留下来的只有一处，可以拿它当判据：总览侧栏那张卡写的是
「紧张 — 2 起事件尚未收束，另有 1 个地区在争夺中」。它是**一句点名了具体东西的话**，
读起来是旁白不是仪表。任务页留的那行「下一次检查 · 霜月13日 07:00」同理——
它是全场最早的一个 
ext_update`，单条在各自卡片上，跨任务和事件一起看才有这个数，
是真正看不见的信息。

契约自己也是这么说的，`macro_record_selection` 那条写着：
**「页面一级信息需要直接回答谁、何时、何地、正在做什么」**。计数和等级一条都不回答。

### 分清「人的事」和「系统的事」

契约是给引擎写的。同一张表里，有些字段描述世界里发生了什么，
有些字段描述引擎自己打算怎么跑——后者混进主视图，整页就会读起来像运行日志。

角色档案页踩得最深：`scene_entry`（这个 NPC 什么条件下能进玩家的场景）
和 `retention`（系统还要不要继续跟踪这个候选人）整整两块都是引擎的账，
`retention` 更是等于把回收策略贴在人物卡上。它们一度和「他在哪、他知道什么」
并排摆着，占的还是靠前的位置。

分法：**玩家扫这一页时会不会想知道这条。** 会，留在主视图；
不会但偶尔要查，进详情或浮层；两者都不是，收进一个明说「这是给引擎看的」的折叠区。
收起来不算删——数据一条不能少，`field-audit.cjs --no-attrs` 会盯着。

现在固定人物与候选人物共用同一套 `profile` 字段：职业、社会角色、年纪、性别、生计、常驻地、专长、外貌和性格标签。`profile` 只进角色档案展示视图，不进入 access 含 macro 的主 API 上下文；副 API 负责原样维护，动态状态仍由后台演进记录负责。

**契约里是两张表，列表里就得是两段。**
pc_updates` 和 `candidate_updates`
字段不同、状态词也是两套（在附近／视线外 对 观察中／可启用）。人物名册原来把两类
按 `updated_at` 混排，只在候选那几张卡右上角挂一枚「候选」角标——同一列里
状态词忽好忽坏，读起来像同一类记录时好时坏。现在分两段、各自按 `updated_at` 倒序，
段头写一次类名，角标跟着删：段头底下每张卡再挂一枚同义标签是重复的话。
翻页翻到半段中间会补一个段头，否则那一页开头认不出是哪类人。

## 版面松紧

信息密度不是越低越好，空得没道理和挤得看不清一样糟。

- 一屏之内同类卡片的呼吸感要一致，不能这张 20px 内边距那张 11px。
- 一大片留白后面跟着一小行字，说明这块的高度是被别的东西撑出来的，去查那个东西。
- 图形区（关系图、拓扑图、时间尺）的高度要跟着内容走，节点少就矮下来，
  不要固定高度然后中间空一大片。
- 长文本区块（事实陈述、依据、变化记录）宽度别超过 ~40 个汉字，超了就分栏或收窄。

### 窄栏放摘要，宽面放全量

侧栏是定宽的（350px 上下），**完整档案不该待在里面**。有两页栽在这上面：
势力档案把 35 个字段塞进 344px 的竖条、堆到 1520px；角色档案的「处境与近况」
八张卡竖着摞成 352×1722。两处都又窄又长，而且把行高压紧只能治「长」治不了「窄」。

看原型是怎么分的。它的侧栏每一节都是**一屏内看得完的摘要 + 一个出口**：

- 势力页：资源储备一整行三项（资金 / 物资 / 情报），外交状态五行一行一条，
  底下「展开更多」；再往下用标签页把三份清单叠进同一块地方。
- 角色页：基础属性 2 列网格、技能倾向 2 列网格、持有物横着一行四个、
  最近接触对象横着一行头像，每节右上角一个「查看全部 ›」。

两页原型都是整页一屏看完，靠的不是少放东西，是**横着铺**加**给出口**。
我们的毛病是把每一节都当成完整清单，一律竖着摞，`kvGrid()` 的列数永远传 1。

所以：

- 窄栏里能横着排的横着排——2 列网格、一行多项、一行头像。
- 每节只留摘要，完整内容走宽浮层（`.sheet` / `.sheet-box` / `.sheet-close`，
  1080px 宽，点遮罩关 / Esc 关 / ✕ 关）。1080px 里字段名和值能同行，
  窄条里被迫竖着叠的东西全能摊平，既不用折叠也不用翻页。
- **浮层默认是关着的，所以摘要里省掉的字段必须在浮层里真的排出来**，别两头都漏。

### 宽度花在多摆一条，不是摊开一条

契约把一条记录拆成五六个字段，是为了让引擎能分别更新——那是**存储**的拆法。
照搬成表格列，每条记录横着摊满一整行，就成了阅读的灾难：势力完整档案曾经是
1080px 五列，每格 150px，装五到十个字，一句「不能同时承担长期封港损失」折成三行，
读的人得自己把句子拼回去。用户的原话是「这些字段实在太碎了，阅读起来就很破碎」。

同样的宽度换个花法：**一行摆两条记录**，每条竖着排，附注能连着写三十几个字不折行。

```
✗ 五列 × 150px            ✓ 两列 × 507px
类型│数量  │当前占用│…      ⬡ 可动用 82,150 金币  [资金]
资金│可动用│港口修复│…        用途 港口修复与临时护卫
    │82,15│与临时护│…        限制 不能同时承担长期封港损失
    │0 金币│卫     │…        ✦ 追加南堤仓库守备预算
```

配套的四条：

- **列数交给 `auto-fit`，别写死两列。**一节里有几条记录是数据说了算：黑石港商会每节两条，
  星辉典籍会每节都只有一条——写死两列就是格格空着右半边，一整份档案看下来右边是条白带。
  `auto-fit` 会把整条空掉的轨道塌掉，一条记录就铺满一行。
  但**卡片撑满不等于字要撑满**：铺满时那格有 1000px，一行能排七十来个字，
  早过了读得舒服的长度，所以值上还得留 `max-width:42em`。
- **主句挑最有信息量的那个字段**（数量、对象名、事实本身），枚举字段做成胶囊跟在后面。
  反过来拿枚举当主句，一列记录的开头就都是一个干巴巴的词。
- **字段名走同一道竖线**（`grid-template-columns:auto minmax(0,1fr)`），值才对得齐。
- **「本轮无变化」是我们补的话，不是数据**，得比真变化淡一档，
  否则一屏扫下来分不清哪条动过。淡到 `--ink5` 会掉出 AA（实测 4.35），
  区别靠图标从主色变灰，不靠把字压得更淡。

### 卡片最贵的是宽度，别拿去养装饰件

活跃事件卡原来是左右两栏：52px 的圆标一栏，正文一栏。344px 的侧栏里，
圆标加间距加内边距吃掉 90px，正文只剩 218px——「下次检查　海盗代表答复停火文本」
后面那个「时」被挤到第二行独自站着，地点也常年折两行。四张卡摞出 700 多 px。

改成**图标跟标题同行，正文和页脚通栏**（原型本来就是这么摆的），
同一份文字拿到 308px：地点、下次检查全部收在一行，卡片从 185/211/164 矮到
140/163/163，摆四张只占原来摆三张的高度。

```
✗ 52px 圆标 │ 218px 正文        ✓ [30] 港口冲突升级      [已控制]
[◯]│港口冲突升级   [已控制]        双方停止靠近民用泊位，临时接触仍在继续
   │双方停止靠近民用泊位，          [冲突] ⚲ 黑石港
   │临时接触仍在继续                ⌂ 下次检查 海盗代表答复停火文本时
   │[冲突] ⚲ 黑石港
   │⌂ 下次检查 海盗代表答复停火文本
   │  时
```

同行之后要收的三个尾巴：

- **带图标的行写成 `14px | 1fr` 的网格，不要 flex。**flex 里那段裸文本是个匿名
  item，折行时第二行落在 item 自己的左边——看着像缩到图标底下去了。
- **圆标跟状态胶囊都咬第一行。**`.chip` 全局是 `align-self:flex-start`，
  圆标也顶格，再用 `margin-top:-4px` 把 30px 的方块骑到 22px 的首行上居中；
  用 `align-items:center` 的话标题一折三行，圆标居中、胶囊顶格，两个各站各的。
- **省下的半个字宽常常刚好够那一行收住。**标签和值之间原来是个全角空格（14px），
  换成 7px 外边距，1280 下三行里有两行就不折了；剩下的交给 `text-wrap:pretty`。

形状也跟着改了：圆形在这套图里是人物头像的形状，事件不是人，
所以圆标换成跟 `.pmark` 一致的圆角方块。

### 东西少的时候，是把盒子收窄，不是把东西摊开

上一条讲的是宽度别浪费在装饰件上，这一条讲宽度别浪费在空气上。角色档案页的
「日程与行动」和「人际关系」是同一个毛病的两种长相，用户圈出来的原话是
「能不能收紧凑一点」。

**日程带：卡片封了 300px 上限。**一天只有一条行动时，702px 的带子只用掉四成，
后面拖着 402px 空白。把上限去掉不等于把小卡吹成一张大牌——卡片一宽，
**卡内改横排**：图标、标题、时间、状态并成一行，地点／任务／事件并成一行，
四五行竖着摞的短句收成两行，面板从 344px 降到 198px。

量宽度用**容器查询**而不是媒体查询：同一张卡在一张、两张、三张时宽度分别是
694 / 342 / 225px，屏幕宽度却没变，媒体查询看不见这件事。三档门槛：

| 卡片内容宽 | 版式 | 出现在 |
|---|---|---|
| < 300px | 全竖排 | 三张及以上 |
| ≥ 300px | 时间和状态胶囊并一行，元信息并排 | 两张 |
| ≥ 440px | 卡头整个并成一行 | 一张（或末行落单的那张） |

门槛量的是**内容盒**：卡片 342px 减掉 24px 内边距只剩 318px，门槛写 320 就永远
不命中。这种差一点点的失手在页面上不报错，表现为"改了没反应"。

顺带一个收获：`flex:1 1 218px` 会让末行落单的卡长满整行，原来靠 `max-width` 摁住，
现在正好让它走宽档——1280 下三条日程排成 2+1，那张落单的自己摊平，没有豁口。

**关系图：画布跟着节点数收。**一条关系的图在 702px 里是两个节点各站一边、
中间一段空连线，两侧再各空一百五十像素。够摆下两个 120px 的节点盒加中间那枚
关系标签就行（一条 460px、两条 580px、三条 680px，四条以上本来就填得满）。
收窄之后右边空出两百多像素，把底下的「往来」清单挪过去并排——摞着是两段高度
之和，并排是取大的那个，面板 349px → 216px。够不够并排是**量出来的**
（`wrap.clientWidth - cap - 8 >= 250`），不是按屏幕断点猜的：1280 下同一个人就自动摞回去。

一个连带的坑：窄屏竖排的门槛 `TIGHT_W` 原来是个常数 470，是为多节点定的。
画布收到 460 之后一条关系的图被误判成窄屏，板高从 172 涨到 286——
**为收紧写的代码收出了一块更高的画布**。门槛跟着节点数走才对。

### 恒高的块提到通栏，会伸缩的块留在栏里

右栏定宽、左栏跟着屏幕变宽，于是屏幕越宽左栏越短、底下空得越明显。
总览的做法是拿真内容去补：关系明细折叠区（约 250px，粗调）和新近事态的每页条数
（约 46px 一条，细调），**先粗后细**，五档空档都压进 45px。补空的东西必须是真内容——
把关系图拉稀、给面板灌内边距都是作弊。

势力页不一样，它的空档来自「各地情势」是**读者自己能开合**的，高度摆 468→2613px。
配平是加载时算的，读者点一下「全部展开」就作废——那 43 行代码是在跟用户的手指赛跑。

第一版改法是把各地情势挪去通栏，让谁都不用跟它比高度。两栏差确实从 526～1619px
变成恒定 60px，但整页从 2180 长到 2412——**通栏的块跟谁都不共享纵向空间**，
本来能跟右栏 1186px 的势力档案并排的 900px，变成了实打实摞在底下的 900px。

第二版反过来：**把恒高的块提到通栏，让会伸缩的块留在栏里当配平的那一头。**

```
世界动向 209 ─┐ 恒高，通栏，摆最上面（也正好是最该先读到的两块）
名录     246 ─┘
────────────────────────────────
势力格局 675  │  势力档案 1186     左栏 = 675 + 各地情势
各地情势 500~ │                    收起时 1187 对 1186
```

结果：收起 1761（原来 1990）、默认 2174、全展开 3442，三档都比原版短，
而收起态两栏差 1px——那正是「地区全收起时中间很空」原本发生的那一档。

判据是**这一栏配平不过来的时候，空的是哪一头**：左栏短，空的是 974px 的主栏，很扎眼；
左栏长，空的是 344px 的窄条，末尾还压着「已推演到」那行，几乎看不出来。
所以让伸缩的那块待在左栏、只往长里跑，是可接受的方向。

后来又试了一次通栏（删掉档案卡三格概览、右栏矮了 162px 之后重量的），结论不变：

| 1536 档 | 各地情势在左栏 | 各地情势通栏 |
| --- | --- | --- |
| 全收起 | 1688px | 2021px |
| 展开一个 | 2101px | 2434px |
| 全部展开 | 3369px | 3667px |

**根因是这一块摊宽了并不会变矮**：收起态每行本来就是一行胶囊，974px 和 1330px
都是一行，宽度对它没用。所以通栏换不来任何高度，只是把它从"跟档案卡共享纵向空间"
改成"自己独占一段"，三档一律加三百多。空档也没省下——它从收起态的 165px
变成三种状态恒定的 347px（势力格局 675 对势力档案 1022）。
**要判断一块该不该提通栏，先量它在两种宽度下的高度差；差不出来就别提。**

剩下两个坑：

- 只调细的那样东西，旁边等高的面板会被拉高后自己空出一块——
  等于把洞从页面底部挪进了面板里，白改。
- 窄屏两栏其实是上下堆的，这时候比高度会把条数越削越少（实测从 5 削到 4）。
  配平前先判断两栏 `offsetTop` 是否相等。

顺带：**面板换了位置，里面的排法要跟着换。** 名录从 344px 的窄栏挪到 1300px 通栏，
原样竖着摞五条就是右边空一大片、页面白长 200px；改成 `auto-fill minmax(290px,1fr)`
之后 246px 装得下，比原来还矮。列宽也得跟着改——名字原来占 `1fr`，
会把状态胶囊一路顶到格子右边，多列下中间空一截，改成 `max-content` 才贴得住。

### 横排摆不下的用箭头翻，不要换第二排

改成横排之后剩一个尾巴：一排放得下四个，五个地区的第五个自己占第二排，
右边空掉四分之三排，面板还平白高一截。用户的话是「一行放不下的不要放两行，
做个左右箭头就行了」。**一整排是这个组件的形状，换行会把形状撑坏；
翻页不会。** 三件事配套：

- **一页放几条 = 一排摆得下几格**，量出来而不是写死（`idxPageSize`，
  跟底部时间线的 `wtlPageSize` 同一招：读 `grid-template-columns` 的轨道数）。
  写死 5 条，1300px 排四格就必然溢出一条。
- **页数定了之后把条目摊匀**，别每页都塞满：五条分两页是 3+2 不是 4+1，
  七条分三页是 3+2+2 不是 3+3+1。末页只站一个，跟第二排只站一个一样难看。
- **最小格宽跟着内容形状走。** 地区一条就是「名字＋状态胶囊」两行短字，230px 够用，
  五个地区一排摆得下，`1536` 上索性不用翻页；热点和关系每条带一两行叙述，300px 才不摞成四行。

同一招也适用于多行的网格，只是量的东西从"一排几格"变成**"几行"**。
总览的人物动态原来写死一页 9 个（照原型的三列九格），七个人就摆成 3+3+1，
末行两格空着，而它本来就是这一页最高的一块。改成 `ACT_ROWS=2` × 当前列数：
宽屏三列 6 人、1440 以下两列 4 人、单列封在 4（单列一页两格翻起来太碎）。
行数比格数好使，因为它跟着断点自己对齐，不会在两列档变成 4+4+1。
断点跨过去列数会变，所以 `resize` 里要重跑一遍。

这里跟上一条的"摊匀"**故意反着来**：横排那种一行的组件，末页只站一个很难看，
所以 5 条分 3+2；多行网格相反，第一页排满整行更重要——七个人 6+1
（首页两行齐平）胜过摊匀的 4+3（首页 3+1，反而多一个豁口）。
判据是**哪一页最常被看到**，把整齐留给它。

摊匀那段算法是 `P.pageSlice(列表, 每页上限, 页码)`，回传 `{items, pages, page}`。
势力页的名录和总览的活跃事件都走它；`page` 要写回调用方自己的页码变量，
不然窗口拉宽之后页数变少，页码会停在一个已经不存在的末页上。
竖排列表跟横排一样吃"末页只站一个"这一亏——一张孤零零的卡下面顶着翻页条，
比多滚两屏更像出了错。

翻页件也换了形状：底下一整行的翻页条（`.pg`，带「第 1/2 页　共 5 个地区」）
对一排格子来说太重，而且又多占一行——换成页签行右端一对圆箭头（`.stripnav`）。
两种翻页件的共同点是按钮上的 `data-d`，`field-audit.cjs` 认这个属性而不是 `.pg` 类名。
副标题那句「共 5 个地区」跟着没了，不算丢信息：底下「各地情势」把地区一条条列着。

## 长得能点，就得真能点

原型是张图，图上的按钮不用管点了以后怎么办；页面不是。一轮 `dead-ui.cjs` 扫出
四页共 10 处死控件、11 处只会弹「尚未接入」的占位，全清了。清的时候按这几条判：

1. **没有数据支撑的，删。** 顶栏的「速度倍率 × 2.0」是四页写死的一个数——契约里
   没有任何间隔、频率、速度字段（`间隔`／`频率`／`interval`／`cron` 全是 0 命中），
   推演由后台的 `bg_world_tick_v09` 驱动，页面是它的显示端，不是遥控器。
   那对「暂停中／继续」同理，是个只会弹吐司的假开关。侧栏的「世界设定」也没有对应产出。
2. **出口指回自己的，删。** 任务与事件页的「查看完整时间线 ›」和「活跃事件 › 查看全部」，
   要看的东西就在本页下面完整分页摆着。
3. **不归引擎管的，删，那句话搬进文档。**「编辑档案」的吐司写着"档案改不了，
   后台世界引擎只负责让世界往前走"——话说得对，但它该在这儿，不该是个按钮。
   「管理角色」「筛选」「搜索」「筛选与排序」同理，纯前端功能没做就先不摆。
4. **有真去处的，接上，别弹吐司告诉人家该去哪儿。** 势力页「完整时间线 ›」原来弹
   "完整世界演进流在世界演进页"，现在直接跳过去。
5. **点了只是复述屏幕上已有的字，等于点了个响。** 总览的事件卡原来挂
   `data-toast="事件名：当前局势"`，那两句就印在卡面上。改成跳到任务与事件页并选中它。
6. **导航项一律要有真页面。** 点了弹「尚未接入」的入口，比没有这个入口更糟：
   它承诺了一个不存在的地方。`NAV` 表里不留空 `href`，`initChrome` 里那条
   `if (!href) toast(...)` 的兜底也跟着删了——留着它就是给下一个人开口子。
7. **不要拿 div 模仿 button。** 事件卡原来一页是 `div` 挂吐司、另一页是
   `div + tabindex` 再手写 Enter/空格的 keydown。它只有「点开这个事件」一个用途，
   那就是 `<button>`，键盘、焦点环、语义浏览器都免费给。

最隐蔽的一种死不在这份清单里，因为按钮本身是活的：**它把活干给了一个不接的人。**
三个页面共五处「点一条任务／事件跳到任务页」都把名字写进 `sessionStorage.focusTask`
再跳，而那一页从来没读过这个键——落地永远是默认选中的第一条，点击的目标静默丢失，
而且看不出丢了。跨页传参必须两头都验一遍，`dead-ui.cjs` 查不出这种。

## 不做静默截断

页面上每个列表都比版面装得下的多。原来的写法是 `slice(0, 4)` 按数组位置切，
切掉哪些完全看运气——曾经把唯一一条受阻任务切没了，而且页面上不留任何痕迹。
现在统一改成：**按 `updated_at` 倒序排，四条一页，其余翻页看**，条数写在翻页条上。
时间轴摆不下 6 个以上，标题里明写「取最近 6 个（共 N 条）」。

同理，`first(a, b, c)` 这种「有 a 就不显示 b」的兜底也清掉了。它看着省地方，
实际效果是只要 `stages[].summary` 有值，`objective`（任务目标）就永远显示不出来。
现在 objective 与阶段摘要、deadline 与 next_update、trigger 与 current_state
各占各的位置。`field-coverage.cjs` 会盯着这件事，契约里 29 个任务／事件字段目前全覆盖。

这两件事查起来各有一个坑，都踩过了：

`field-coverage.cjs` 一度只有 `faction_updates` / `region_updates` 两组，
也就是四页里只覆盖了一页，而它的绿字被当成了四页的保证。现在七组齐全，
并且写死了**每组由哪一页负责排全**（`OWNER`）——别处出现的是摘要，不算落点。
契约里确实不该给玩家看的字段（`change_updates.change_key` 这种技术去重键）
单列进 `EXEMPT` 并写明理由，跟「漏了」区分开。

`field-audit.cjs` 一共踩过三个坑，每个都会让它输出假绿：

1. **看不见关着的浮层。**`hidden` 的 `.sheet` 是 `display:none`，正文一个字都不在
   `innerText` 里，但里面元素的 `title` 照样被抓到。三页都在走「窄栏摘要 + 宽浮层」
   之后，这个盲区会逼着页面在摘要行上挂一堆 `title` 去糊审计——而 `title` 恰恰是
   下面那条说的会消失的落点。现在抓文本前先点开出口再取消隐藏（顺序不能反，
   内容是点开时才渲染的），另外加了 `--no-attrs`：只认可见文本。
2. **只认得角色档案页。**「查哪些记录、怎么点开第 n 条」原来是写死人物列表的，
   给另外三页传文件名只会得到一句「查 0 项」——而重构那几页的时候恰恰最需要它。
   现在写在 `PAGES` 里，四页各一份，`--all` 一次跑完。改了记录的点开方式要跟着改这里。
   顺带统一了浮层入口的标记：凡是点开会另开一层的按钮都挂 `data-open-sheet`
   （三页原来各叫 `.dmore` / `#openFull` / `#dossierBtn`，审计只认得其中一个，
   于是另外两页的浮层内容从来没被审过）。
3. **翻页翻走的当成了丢。**列表分页是刻意取舍，跟「这条字段根本没排」是两回事。
   不翻一遍，凡是超出首页的记录都会被报成数据丢了，然后逼着页面取消分页去糊审计。
   现在每查一条记录前先把所有翻页条退回第一页，再逐页往后扫着抓文本。

三个坑填完，四页 624 个字段值 × 三档宽度全绿——在此之前只有角色档案一页是真被审过的。

还有一种更阴的漏法：**装饰性元素不能是某条契约字段的唯一落点**。
角色档案的 `schedule[].end_time` 一度只写在时间尺刻度的 `title` 里，而刻度会因为
版面变窄被挤掉——于是这条字段读不读得到取决于窗口多宽，1536 下审计永远是绿的。
凡是会随版面收起、折叠、改写的东西（时间尺刻度、并排才出现的副栏、悬停提示），
都要保证同一份信息在别处还有一个不会消失的落点。`field-audit.cjs` 因此改成三档都跑，
并会单独列出「换个宽度就找不到」的字段。

真正的清理该在数据层做——这些数据每轮都要回填进上下文，是实打实的 token。
见 `数据层待办.md`。页面这边只负责不隐瞒。

排序依赖时间可解析，而架空历法的月份是名字不是序号（`霜月` 排在 `花月` 前还是后，
程序无从判断）。`shared/wtime.js` 现在按「先在数据里出现的月份算更早」兜底，
同月内准确，跨月是猜的。根治办法也在 `数据层待办.md` 里。

## 改数据或改词典之前

`shared/vocab.js` 里每一组都对应契约中的一条枚举约束，组名后的注释写明了出处。
取标签必须带组名——同一个字符串在不同组里含义不同，例如 `planned` 是日程状态
（`schedule.status`）而不是阶段状态（`stage.status`，那里用的是 `available`）。
遇到词典里没有的值，`V.label` 会在控制台告警并原样返回，让契约漂移暴露出来，
而不是把英文枚举默默渲染给用户。

### 关于「主线任务」

契约对 `task.category` 的原文是：

> 只使用 main_task、side_task、character_task、faction_project、personal_task、other；
> **只有输入明确时区分主线和支线**。

宏观模块 `macro_task_creation` 里另有一条：「主线、支线等分类只在输入已有明确归类时采用，
**不由后台自行宣布**」。后台自主演进出来的任务默认落在 `character_task`、`faction_project`、
`personal_task` 这几类里，界面上不应该出现「主线」字样。上一代 demo 用的
`commission` / `investigation` / `escort` / `world_task` 全都不在枚举内。

## 建 mock 时修掉的契约违规

旧 demo 数据有 11 处枚举越界，接真实产出时会直接暴雷，已在 `build-mock.cjs` 里逐条修正：

| 位置 | 旧值 | 契约值 |
| --- | --- | --- |
| `tasks[].category` | `commission` / `investigation` / `escort` / `world_task` | `character_task` / `faction_project` |
| `tasks[].stages[].status` | `planned` | `available` |
| 
pcs[].knowledge[].status` | `likely` | `uncertain` |
| `events[].participants[].type` | `region` | `group` |
| `regions[].control.status` | `disrupted` / `open_with_restrictions` / `open` | `controlled` |
| `regions[].conditions[].category` | `transport`、`economy` | `travel`、`commerce` |
| `factions[].resources[].type` | `records` | `information` |
| `factions[].areas[].relation_type` | `contest` | `contested` |

另外补了两处缺失：

- **`changes` 集合**旧 demo 完全没有，而总览页需要它。现按契约从已完成的任务阶段、
  事件公开后果和地区变化派生，`change_key` 固定为 `time|kind|source_type|source_name|target_name`。
- **好感度**：契约里 
pcs[]` 和 `candidates[]` 的 `relations[]` 必带 `favorability`
  （0–100，50 为中性熟人）和 `favorability_change`，旧 demo 整个字段都没有。
  注意 `factions[].relations[]` **没有**这两个字段，好感度是人物专属概念。

`regions[].control.status` 这一组值得单独说：旧数据把「通行受限」「秩序被破坏」这类
**地区条件**误写成了**控制状态**，但这些事实本来就已经记在 `conditions` 里，控制方并未改变。

## 原型上有、契约里没有的东西

四张原型图里画了一批数字，契约中并不存在，而且宏观规则明令禁止后台生成：

| 原型上的东西 | 契约实情 |
| --- | --- |
| 地区繁荣度、治安进度条 | `region_updates` 只有 `conditions[].fact` / `impact`，是事实不是评分 |
| 势力影响力 68/100、资源精确数字条 | `resources[].quantity` 是事实性字符串，明确要求「不自行制造精确数字」 |
| 人物基础属性、技能 LV、持有物 | 不属于后台世界引擎契约，不在面板占位 |
| 健康／体力／信任／好感四条状态槽 | 只有 `relations[].favorability`（0–100）是真的，其余三条没有来源 |

处理办法统一是**构图照抄，数字不编造**：位置和控件保留，但进度条只表达能从枚举推导的
强度（如 `control.status` 五档、`areas[].relation_type`），推导口径写进元素的 `title`；
没有数据来源的部分做成明确空态，说明等哪一路数据接入。要让这些真的有数，
得在契约里加字段，不是前端补。

空态别画成 0%。一条 0% 的实心进度条会被读成「这个数值是零」，而真相是后台根本不产出
这个数。角色档案用的是虚线胶囊（`.ghost`）：实心／描边表示「有值」，虚线表示「没有值」，
两者一眼分得开。目前只有那一页在用，第二个页面要表达同一件事时就该提进 `console.css`，
否则同一句话会长出四个样子。

## 还没做的

- **美术资产**，缺口、规格和分配规则见 `美术资产清单.md`。数据是 AI 每轮实时产出的，
  页面不知道渲染的是哪个人物、势力、地区，所以资产按可组合的通用件来做，不按实体出图。
  控制台那三个 404 是已知的装饰缺件，页面已做留白降级不会破图。
- **翻到 `changes` 末尾时没有说"到头了"**。那 120 条是视图给的上限，翻完不等于世界
  从那天开始——这正是「不做静默截断」那一节要求说出来的那种边界，翻页条现在只报
  「第 n / m 页　共 N 条」，没说 N 是被截过的。要等真接上后端、能拿到"是否还有更早"
  才好说，现在 mock 只有一轮 16 条，做了也验不出来。
- **`outcome` 这条路没跑过**。任务和事件终止后才有 `outcome`，当前 mock 里五条任务
  四条事件全是进行态，所以渲染代码写了但没有真数据走过。等 mock 里出现终止态条目
  （或者接了真实产出）要回头看一眼版式。
- **时间尺的防叠字只有角色档案有**。刻度取值是各页面自己算的，「等距挑第几个时间点」
  挑出来的不是等距的时间——赛文那天中间两个刻度只差五十分钟，390 档下相隔三十来像素
  直接糊成一团。角色档案加了按实际像素间距回收的逻辑，总览那份还没有。
  这段该做成 `P.renderRuler(元素, 时间串, {最小间距})` 收进 `panel.js`，两边共用。
- **暗底还没有令牌**。势力与地区的关系图是全站唯一一块深色画布，色值写死在那一页里
  （夜空往紫偏、地面掺赭石，跟暖白纸面同族，不能用冷灰蓝）。总览的「所有人的往来」
  浮层以后要走暗底就会各写一套，那时候在 `tokens.css` 开一组 `--night-*`。
- **标题字号还差一档没定死**。`.phead h2` 是 20px、`.dcard-h` 17px、`.sech` 15px。
  后两个目前只有角色档案在用，真要进共享层应该三档一起定成
  「面板 20 / 卡片 17 / 块内 15」，而不是单挪一个。
- **三页的栏高差没收**（1536 档量栏高）：任务与事件 1216 / 897（差 319），
  势力与地区收起态 1187 / 1022（差 165）、展开一个地区 1600 / 1022（差 578），
  角色档案 811 / 1418 / 1081（差 607）。总览靠 `balance()` 已经收到 61。
  差出来的就是页面底部那块白。**别拿加内容去填**——概览格当初就是这么长出来的。
  三条路都试过，只有第一条能用：换栏（总览的 `balance()`）；提通栏（势力与地区
  试过两次，每次都更长，见下）；靠数据自然长满（mock 里 `SUM_MAX=4` 根本没触顶，
  加不出内容来）。
  势力与地区那 165px 是删档案卡三格概览时空出来的，删之前两栏收起态只差 3px——
  纯属那三格恰好 162px 高，不是配平做对了。展开一个地区才差 578，
  那是手风琴张开的正常结果，不是版式漏洞。
- **两个工具有已知盲区**。`type-probe.cjs` 量得出字号、行高、字重、对比度，
  量不出「13px 用在了字段值上」「字段名没上主色」这类角色错配，只能靠眼睛。
  （它跟 `field-audit` 犯过同一个错：看不见关着的浮层，而浮层恰恰是排全量字段、
  字号最容易悄悄掉下去的地方。现在也先点 `data-open-sheet` 再量。）
  `graph-probe.cjs` 把所有 `path[stroke]` 都算成连线，所以画装饰路径必须写
  `style="stroke:..."` 而不是 `stroke` 属性，否则地平线和罗盘会被算成边。
